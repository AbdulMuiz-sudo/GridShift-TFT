\begin{abstract}
This report details the execution of Phase 3 (Data Architecture \& Preprocessing) and Phase 4 (Modeling \& Evaluation) for the GridShift project. The objective is to forecast hourly electricity demand in India by integrating multi-frequency SCADA JSON data with tabular reports. The modeling phase contrasts a baseline XGBoost regressor—fortified with target differencing to handle temporal distribution shifts—against a deep learning Temporal Fusion Transformer (TFT).
\end{abstract}

\section{Phase 3: Data Architecture \& Preprocessing}
The data pipeline was engineered to unify disjoined formats from 2021-2025. The preprocessing architecture executes the following deterministic steps:
\begin{itemize}
    \item \textbf{Format Auto-Detection:} Dynamically parses nested SCADA JSON strings and standard Excel tabular sheets, resolving string formatting inconsistencies (e.g., erratic quotes, array wrappers).
    \item \textbf{Frequency Alignment:} High-frequency SCADA readings (10-second/5-minute) are aggregated and resampled into a strict 1-hour temporal index.
    \item \textbf{Imputation:} Short periods of missing data (up to 3 hours) are resolved via time-based interpolation to maintain chronological continuity without introducing artificial data.
    \item \textbf{Temporal Splitting \& Leakage Prevention:} The dataset is partitioned chronologically (70\% Train, 15\% Validation, 15\% Test). A \texttt{StandardScaler} is fitted exclusively on the training partition to prevent look-ahead bias before transforming the validation and test sets.
\end{itemize}

\section{Phase 4: Modeling Architecture}
The forecasting task is approached via two distinct architectures to evaluate the tradeoff between interpretable tree-based ensembles and deep sequence models.

\subsection{XGBoost with Target Differencing}
Initial baseline evaluations of the XGBoost model revealed a significant distribution shift (Validation MAE: $\approx 4,997$ MW vs. Test MAE: $\approx 8,119$ MW). Because tree-based models fail to extrapolate absolute load growth over time, the architecture was re-engineered:
\begin{itemize}
    \item \textbf{Differencing:} The target variable was transformed to predict the step-change ($t+1$ minus $t$) rather than absolute load.
    \item \textbf{Feature Engineering:} Introduced 24-hour and 168-hour (7-day) rolling means, alongside temporal cyclic features (Sine/Cosine transforms for Hour, Day, and Month).
    \item \textbf{Regularization:} Applied \texttt{subsample} and \texttt{colsample\_bytree} at 0.8 to penalize memorization of training noise.
\end{itemize}

\subsection{Temporal Fusion Transformer (TFT)}
The TFT model leverages a 168-hour lookback window to predict a 24-hour horizon. Utilizing PyTorch Forecasting, the architecture inherently maps time-varying known variables (cyclic time features) and time-varying unknown variables (historical load, solar, and wind data), optimizing over a Quantile Loss function.
